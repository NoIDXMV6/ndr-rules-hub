Сборка образа снова падала: `bun install` 45 минут молча висел и был убит предохранителем на деградировавшем зеркале (v1.36.1).

Причина (диагностика продакшена): зеркало `npm-mirror.gitverse.ru` деградировало по пропускной способности — манифест `/next` (~31 МБ) отдаётся ~16 с против 0.4 с у `registry.npmjs.org` и 0.7 с у `registry.npmmirror.com` (лёгкий манифест `/ms`, ~90 КБ: 0.04 / 0.34 / 1.4 с). Холодная установка ~1000 пакетов не уложилась в предохранитель 2700 с; bun в non-TTY не печатает прогресс, поэтому сборка 45 минут выглядела «зависшей с нулевым выводом» (`bun install v1.2.23` в баннере — и тишина до kill). Сценарий инцидента v1.27.0 повторился в другой форме: тогда висела сеть до единственного дефолтного реестра, теперь — единственное ЗАДАННОЕ зеркало. Один реестр больше не судьба сборки.

scripts/bun-install.sh (новый; этап deps Dockerfile вызывает его вместо прямого bun install):
- ПРЕДПРОВЕРКА каждого зеркала-кандидата: полный GET `/ms` (лёгкий манифест ~90 КБ) с таймаутом 15 с, замер полного времени ответа; пробует сам bun (curl в образ deps может не входить). Нет ответа / HTTP ≠ 200 → зеркало исключается сразу: время предохранителя на попытку не тратится.
- Порядок попыток — по возрастанию времени ответа; зеркала медленнее BUN_SLOW_MS (3000 мс) — в конец очереди: быстрый ответ на маленький манифест не спасёт установку тысяч пакетов на задохнувшемся зеркале (как раз случай gitverse: `/ms` — 1.4 с, но `/next` — 16 с).
- Каждая попытка: `bun install --frozen-lockfile --registry <зеркало> --network-concurrency 16 --verbose` под предохранителем `timeout --kill-after=30`. BUN_INSTALL_TIMEOUT теперь секунды НА ПОПЫТКУ (дефолт 900; раньше — общий на шаг 2700): при трёх зеркалах худший случай ограничен, но сборка получает три независимых шанса. `--verbose` — в логе сборки видно, на каком пакете остановились (диагностика «молчаливого» зависания).
- Первая удачная попытка завершает шаг («OK: зависимости установлены с <зеркало> за Nс»); FAIL с полной диагностикой в stderr — только если не сработало ни одно зеркало (конвенция v1.36.0: ошибки — в stderr).
- Кандидаты: NPM_REGISTRY (если задан — предпроверяется ПЕРВЫМ, но в очередь попыток встаёт по фактической скорости) + дефолтные `registry.npmjs.org` → `registry.npmmirror.com` → `npm-mirror.gitverse.ru`; дубликаты убираются, trailing-слэши нормализуются. Свой полный список — `BUN_REGISTRIES="url1 url2 …"` (например, своё зеркало).
- DRY_RUN=1 — только предпроверка и вывод порядка попыток (без установки): быстрый health-check зеркал с хоста.
- bun.lock не содержит URL реестра (только integrity-хэши) — установка с любого зеркала детерминирована, целостность каждого пакета проверяется по lockfile.

Dockerfile (этап deps): `COPY scripts/bun-install.sh`, ARG `NPM_REGISTRY=` (пусто = авто-выбор самого быстрого), `BUN_INSTALL_TIMEOUT=900` (на попытку), `BUN_REGISTRIES=`, `BUN_SLOW_MS=3000`; комментарий-история инцидентов переписан (v1.27.0 → v1.36.1). docker-compose.yml: дефолты args обновлены (NPM_REGISTRY пуст — авто; BUN_INSTALL_TIMEOUT 900), комментарий описывает автоматику и все ручки. .env.example: секция «Сборка образа (этап deps)» переписана.
