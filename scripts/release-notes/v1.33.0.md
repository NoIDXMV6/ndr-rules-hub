# v1.33.0 — полный Uri с токеном для DNS-списка; автоподнятие WireGuard-туннеля

Исправление по обратной связи: для списка заблокированных доменов выдаётся
**полный Uri с токеном в адресе** (DNS-серверы не имеют отдельного поля для
ключа — список могут забирать любые серверы с обновлением по ссылке, без
привязки к Clear NDR). Плюс автоматическое поднятие WireGuard-туннеля при
старте контейнера по переключателю в настройках.

## DNS-токен: полный Uri с токеном («Аккаунт → Токены и доступ»)

- **Плашка после создания токена зависит от scope** — у двух списков разные
  процедуры подключения:
  - **правила Suricata** (scope «правила»/«оба списка») — как раньше: Uri БЕЗ
    токена (`/api/export`, `/api/export?archive=1`), токен вставляется в поле
    «Optional authorization key» источника Clear NDR (заголовок Authorization);
  - **список заблокированных доменов** (scope «домены»/«оба списка») —
    **ПОЛНЫЙ Uri с токеном**: `/api/dns/export?token=ndrt_…` — вставляется
    ЦЕЛИКОМ в поле URL/адреса списка DNS-сервера. Потребители — **любые
    DNS-серверы с обновлением списков по ссылке** (AdGuard Home, Pi-hole,
    Blocky, dnsmasq и другие): отдельного поля для токена у них нет. Токен в
    URL-кодировке, адрес самодостаточен; заголовок Authorization также
    принимается, но не требуется;
- **scope «оба списка» — две секции**, каждая с полной информацией по своему
  типу: «1) Правила Suricata — источник URL в Clear NDR (Uri без токена)» и
  «2) Список заблокированных доменов — полный Uri с токеном для любого
  DNS-сервера», плюс примечание о различии процедур подключения;
- обновлены подсказки карточки токенов (ru/en): описания карточки
  (descAdmin/descUser), примечание о постоянстве Uri (для правил меняется
  только ключ в authkey, для DNS-списка обновляется полный Uri целиком),
  пошаговая инструкция дополнена шагами 8–9 (подключение DNS-сервера и
  проверка `curl -s "<Uri с токеном>"`);
- хелперы адресов вынесены в клиент-безопасный модуль `src/lib/serve-urls.ts`
  (`rulesExportUrls`, `dnsExportUrl`) — без серверных импортов;
- серверная часть не изменилась: `GET /api/dns/export` и раньше принимал токен
  из `?token=` и заголовка Authorization; подсказки при отказе в доступе уже
  вели к `?token=`.
- подсказка отдачи на вкладке «DNS списки → Сборка и экспорт» переписана: в ней
  показан вид полного Uri с токеном.

## WireGuard: «Автоматическое поднятие тунеля» (wgAutoUp)

- Новая карточка на вкладке **«Интеграции → WireGuard VPN»** с переключателем
  **«Поднимать туннель автоматически при старте»** (настройка `wgAutoUp`,
  по умолчанию выключена) и бейджем состояния («автоподъём вкл/выкл»);
- при старте контейнера (хук `src/instrumentation.ts` — один раз на процесс,
  с паузой 7 с, чтобы сервер успел начать слушать порт; страховочный вызов
  из bootstrap дашборда) выполняется проверка доступности конфигурации и
  подъём:
  1. профиль в БД: сначала помеченный active (последний поднятый), иначе
     первый сохранённый;
  2. конфиг валиден (parseWgConfig: [Interface]/PrivateKey/[Peer]);
  3. туннель ещё не поднят (`wg show interfaces`) — после рестарта процесса
     без пересоздания контейнера ничего не выполняется;
  4. `wg-quick up` — с прежними механизмами: full-tunnel-исключение трафика
     web UI, очистка «полуподнятых» интерфейсов;
- **включение переключателя сразу выполняет попытку подъёма** (действие
  `POST /api/vpn {action:'auto-up'}`), результат — в сообщении на вкладке,
  журнале и уведомлениях; при выключенном переключателе подъём возможен
  только вручную;
- исход операции сохраняется в профиль (lastStatusJson с пометкой `autoUp`),
  журнал (scope vpn) и уведомления Telegram/Gotify (notifyOnVpn);
- в GET `/api/vpn` добавлено поле `autoUp`; в openapi.json — действие
  `auto-up` и описание;
- планировщик конвейера (правила + DNS-цикл) теперь **автоматически
  восстанавливается при старте процесса** (`maybeStartScheduler`, bootstrap
  дашборда): после рестарта контейнера cron-расписание работает без
  пересохранения «Настроек».
