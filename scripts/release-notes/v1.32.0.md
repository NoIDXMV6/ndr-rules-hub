# v1.32.0 — DNS-сборка зеркальна «Сборке итогового набора»; DNS-цикл в расписании и уведомлениях

Развитие DNS-модуля по обратной связи: страницы сборки правил и доменов выглядят
единообразно, DNS-цикл стал полноценной частью расписания и уведомлений — со своим
временем (разнос пиков) и своей строкой в Telegram/Gotify.

## «Сборка списка заблокированных доменов» — аналогично «Сборке итогового набора»

Вкладка «DNS списки → Сборка и экспорт» (`dns-build-tab.tsx`) переписана зеркально
`build-tab.tsx` (правила): для пользователя обе страницы сборки выглядят одинаково.

- **Кнопка сборки в шапке карточки** («Собрать список», иконка пульсирует во время
  работы); настройки итогового файла — компактной сеткой в три колонки: формат
  (plain/hosts/dnsmasq/AdGuard), имя файла, ключ отдачи;
- **прогресс с фазой и терминальным журналом**: тёмная консоль с автопрокруткой
  (`pre`), локализованные фазы `dns.progStage` (чтение источников → слияние и
  дедупликация → рендер → сохранение → готово), процент; сборка, запущенная другим
  окном или cron, подхватывается при открытии вкладки (`showProg = busy || active`);
- **бейджи последней сборки** — как у правил: время, «{n} доменов» (с иконкой),
  размер, имя файла, короткий sha256 (полный в подсказке), бейдж cron/вручную
  (cron — синий), кнопка «Скачать список» справа;
- **сетка показателей** (7 карточек MiniStat): записей на входе, дубликаты,
  исключено белым списком, исключено категориями, исключено вручную, TLD-записей,
  итог (доменов в файле) — данные из `DomainMergeStats` записи `DomainBuild`;
- **таблица по источникам** с закреплённой шапкой и прокруткой: источник,
  записей, в сборке (зелёным), дубликатов, белым списком, категориями (жёлтым),
  вручную (красным);
- **карточка «Файлы в каталоге экспорта (data/exports/domains)»** — зеркально
  карточке файлов правил: имя, размер, время, ссылка «последний файл»;
  список отдаёт `GET /api/dns/build` (расширен ответ: `{ build, files }`);
- адрес отдачи и подсказка про токены сохранены (блок под таблицей);
- итог сборки — сообщением как у правил («Сборка завершена: N доменов → файл»,
  зелёным; ошибка — красным).

## DNS-цикл в «Расписании (cron)» — разнос пиков нагрузки

- В карточке «Настройки → Расписание (cron)» появился блок **«DNS-цикл»**:
  переключатель «Обновлять DNS-источники и пересобирать список доменов»
  (`dnsCronEnabled`) и поле **«Отдельное расписание DNS-цикла»** (`dnsCronSchedule`,
  placeholder «30 4 * * *»);
- **три режима** (`dnsCycleMode()` в `service.ts`): `inline` — DNS выполняется сразу
  за основным циклом (расписание пусто или неверно — как раньше); `deferred` —
  планировщик запускает **вторую cron-задачу** по отдельному выражению (правила
  утром, домены позже — пиковая нагрузка разнесена); `off` — DNS-цикл выключен
  настройкой;
- при неверном выражении — **предупреждение в журнале** («DNS-расписание … не
  применено: неверное cron-выражение — DNS выполняется вместе с основным циклом»)
  и откат к совместному запуску; при корректном — журнал «DNS-цикл запущен по
  отдельному расписанию … (разнос с основным циклом)»;
- `runPipeline` при `deferred` не дублирует DNS-работу, а уведомление полного цикла
  сообщает: «DNS: отдельный цикл по расписанию «…» — обновление источников и сборка
  списка выполняются отдельно (разнос пиков)».

## DNS-строка в уведомлениях Telegram/Gotify

- Новый scope событий **`dns`** в `notify.ts`: строка «DNS-списки», переключатель
  **notifyOnDns** в «Интеграции → Уведомления и сервисы → События» (по умолчанию
  включён);
- отдельный DNS-цикл (`runDnsCycle`, вызывается второй cron-задачей) шлёт
  **собственное уведомление**: заголовок «DNS-цикл (cron): список доменов собран —
  N доменов» / «Ошибка DNS-цикла: …», строки «источники: успешно X, ошибок Y
  (всего Z)» и «сборка списка: N доменов → файл»; уровень success/warn/error;
- при совместном запуске итоги DNS по-прежнему входят в уведомление полного цикла
  строкой «DNS: источники X/Z успешно, список доменов: N доменов» (с v1.29.0).
