# v1.29.0 — DNS-фильтрация: доменные списки, импорт SQL-базы, список заблокированных доменов

## Что нового

Новый модуль **«DNS списки»** (меню второго уровня, только администратор) — та же идеология,
что у правил для NDR, но записи — домены: источники → категории/записи → сборка → отдача по токену.

### Меню второго уровня (единообразно с правилами)

- Первый уровень держит только группы: **Обзор · Правила · DNS списки · Интеграции ·
  Администрирование · Справка** — меню снова помещается целиком;
- **«Правила»**: Источники / Категории / Правила / **Сборка и экспорт** (переехала с
  первого уровня);
- **«DNS списки»** (зеркально): Источники / Категории / Записи / Сборка и экспорт;
- прежняя вкладка-«табы» DNS-фильтрации разделена на 4 самостоятельные вкладки
  (dns-sources/categories/records/build), группировка функционала логичная и одинаковая.

### Источники доменных списков

- **Каталог 46 списков** (AdGuard HostlistsRegistry, hosts-фиды): от «HaGeZi's Threat
  Intelligence Feeds» (1,6 млн) до региональных (POL/SWE/TUR/VNM/Ukraine) и белого списка
  HaGeZi Allowlist Referral; приоритеты по уровням — угрозы 20 → фишинг 21 → трекеры 30 →
  тематические 40–45 → реклама 50 → смешанные 60 → allow 90.
- Разбор форматов: **adguard** (`||домен^`, TLD-записи `||top^`, исключения `@@||домен^`),
  **hosts** (`0.0.0.0 домен`), **plain**; автоопределение.
- **Импорт базы фильтрации** (`POST /api/dns/import`, файл export.sql или .rar): потоковый
  разбор SQL-дампа MariaDB/HeidiSQL — 502 МБ ≈ 22 с, ~2,2 млн доменов (тип «Domain name»)
  и 151 категория дампа → `DomainCategory` (`ifaro:<номер>:<Eng>`); счётчики категорий
  кэшируются в настройке `dnsIfaroCategoryCounts`; дубликаты дампа (один домен из разных
  resource-строк и из URL) дедуплицируются при импорте.

### Конвертация прочих типов дампа в правила NDR (v1.29.0)

Записи URL/IP/CIDR/Regex/Phrase — легитимная часть базы, но DNS-блокировка работает только
по доменам, поэтому они конвертируются по своим типам (ничего не теряется):

- **URL** → доменная часть (хост) попадает в DNS-список с категориями дампа, сам URL
  становится HTTP-правилом (`http.host` + `http.uri`, drop, SID 1 300 000+);
- **IP/CIDR** → IP-правила чанками по 500 адресов на SID (`drop ip`, SID 1 200 000+);
  приватные/служебные диапазоны (10/8, 127/8, CGNAT, link-local и др.) отбрасываются;
- **Regex** → pcre-правила на `http.uri.raw` (drop, SID 1 400 000+); шаблон валидируется
  компиляцией, слишком широкие (матчат всё подряд) отбрасываются;
- **Phrase** → правила по содержимому ответа `http.response_body` (drop, nocase,
  SID 1 500 000+) — кириллица матчится по UTF-8 байтам;
- правила пишутся в `data/domains/ndr/dump-{ip,url,regex,phrase}.rules` с шапкой и
  регистрируются как источники **«Дамп фильтрации: …» ВЫКЛЮЧЕННЫМИ** (правила загружаются
  в БД сразу — счётчик честный; в сборку попадают только после включения в
  «Правилах → Источниках»);
- ответ импорта и журнал содержат счётчики по типам (URL/IP/CIDR/Regex/Phrase →
  сгенерированные правила).

### Записи, категории, дубликаты

- **Поиск по домену** сразу по всем источникам (видны все вхождения — дубликаты) и
  **топ дубликатов** (`/api/dns/records?duplicates=1`).
- **Ручные решения** (`DomainOverride`, переживают обновление источников): «исключить из
  сборки» и «принудительный блок поверх белого списка».
- **Категории**: у источников — одна, у доменов SQL-базы — несколько (домен остаётся в
  сборке, пока включена хотя бы одна); выключенная категория источника убирает его домены.

### Сборка и отдача

- **Сборка списка заблокированных доменов** (`buildDomainList`, фон + прогрессбар
  `/api/dns/build/progress`): дубликат достаётся источнику с меньшим `priority`, белый
  список применяется в конце; записи подаются лениво (AsyncIterable из курсора БД —
  миллионы строк без загрузки в память).
- **4 формата файла**: plain (домен в строке) / hosts (`0.0.0.0 d`) / dnsmasq
  (`address=/d/`) / adblock (`||d^`) — настройка `dnsBuildFormat`, имя — `dnsFileName`.
- **Новый пойнт скачивания `GET /api/dns/export`** — по аналогии с `/api/export`: очередь
  загрузок, rate-лимит, аудит.

### Токены скачивания: scope

- `DownloadToken.scope`: **rules** (правила, дефолт для старых токенов) / **domains**
  (список доменов) / **both** (оба списка). Выбор scope при создании токена на вкладке
  «Сборка и экспорт»; в таблице токенов — колонка «Доступ», в плашке созданного токена —
  адрес `/api/dns/export` для scope domains/both.
- Токен «только домены» к правилам доступа не имеет (внятный ответ 403) и наоборот.
- Глобальный ключ отдачи списка доменов — настройка `dnsServeToken` (секрет, скрывается
  от не-администраторов); сессия веб-интерфейса скачивает без ключа.

### Проверено на реальном дампе (smoke)

- Полный дамп 502 МБ: 5 630 750 строк → **2 207 508 доменов**, 151 категория,
  2 316 884 связи домен-категория, 505 101 прочих типов (URL/IP/…), 4 269 некорректных
  доменов, 21,5 с.
- Seed 46 источников → загрузка yoyo (3 567) и mvps (8 729) по сети → импорт обрезанного
  дампа (113 863 домена) → сборка: 125 716 доменов, 443 дубликата устранены.
- UI: меню «DNS списки» с подменю, все четыре вкладки, сборка из интерфейса,
  `GET /api/dns/export` отдаёт файл с заголовком и списком источников.
- Сквозной тест конвертации (тестовый дамп со всеми типами через `POST /api/dns/import`):
  домен + хост URL в DNS-списке с категориями, 1 IP-правило (2 индикатора, приватный
  отброшен), 2 HTTP-правила, pcre- и response_body-правила; 4 выключенных источника
  «Дамп фильтрации: …» с загруженными правилами; повторная DNS-сборка включает
  импортированные домены.

## Анализ дампа (отчёт)

`ifaro-dump-analysis.md` / `ifaro-intersection.json` (в репозитории не версионируются,
выданы пользователю): дамп 19.11.2026 — 2,2 млн уникальных доменов, 151 категория,
18 внутренних источников (EAIS.RKN, PhishTank, OpenPhish, CTTFeeds и др.). Пересечение
с 36 DNS-списками хаба: Phishing Army — 83,7 % совпадения, OISD Big — 32,6 %, yoyo — 54,3 %;
**88,2 % доменов дампа не покрыто ни одним списком** — база существенно дополняет каталог;
обратно, 90,6 % доменов списков отсутствуют в дампе — списки дополняют базу.
