Три проблемы одним релизом: потерянный в v1.36.1 скрипт сборки, инцидент «БД 1.3 GB → код 2 до докатки схемы → P2022 → вечная „Проверка сессии…"» и слепота UI при сбое сессии.

1. Сборка образа: scripts/bun-install.sh не попал в коммит v1.36.1 (белый список `/scripts/*` в .gitignore — тот же механизм, что и потеря repair-скрипта в v1.11.0): `git add -A` молча игнорировал новый файл, у пользователей сборка падала на `COPY scripts/bun-install.sh: not found`. Исправлено: `!/scripts/bun-install.sh` в .gitignore, скрипт закоммичен (v1.36.2).

2. Инцидент продакшена «после авторизации висит „Проверка сессии…", БД 1.3 GB». Цепочка: скан целостности quick_check(25) на БД тома 1.3 GB не укладывался в 90 с → db-heal завершался с кодом 2 («не успел») и обрывался ДО докатки схемы → сервер стартовал с устаревшей схемой тома → все API падали P2022/P2021 → /api/auth/me падал → UI вечно показывал спиннер «Проверка сессии…» без всякой диагностики (сбой молча держал me === null). Лечение:
   - db-heal.cjs: НОВЫЙ порог DB_HEAL_CHECK_SKIP_MB (дефолт 400 MB) — на БД больше порога скан целостности ПРОПУСКАЕТСЯ с явной строкой в логе («скан целостности пропущен: БД … MB > порога … ; полный скан вручную: NDR_DB_FULL_CHECK=1»). Докатка схемы выполняется ВСЕГДА: она читает только метаданные (sqlite_master + PRAGMA table_info) и на страницах данных не зависит. `0` — сканировать всегда (поведение до v1.36.2).
   - db-heal.cjs: ТАЙМ-АУТ скана больше не обрывает скрипт до докатки — повреждённость не доказана (структурная проверка пройдена), докатка выполняется, сервер стартует со свежей схемой вместо устаревшей. Раньше любой тайм-аут скана на большой БД гарантированно оставлял сервер на старой схеме.
   - docker-compose.yml/.env.example: DB_HEAL_CHECK_SKIP_MB (дефолт 400) задокументирована.
   - Коды выхода db-heal не менялись; код 2 остался для тайм-аутов структурной проверки/подключения.
