# v1.40.1 — живучесть скана живости доменов: чекпоинт, промежуточный сброс вердиктов, автовозобновление

Прерывание скана живости доменов (проверка делегирования, dns-alive.ts) больше не
теряет результаты и не требует ручного перезапуска. Первичный прогон по миллионам
доменов идёт часами и днями — теперь рестарт контейнера не обнуляет работу.

## Промежуточный сброс вердиктов

- раньше вердикты писались в `DomainAlive` только по границе партии 25 000 — рестарт
  посреди партии терял до 25 000 проверок (при пессимистичных таймаутах — до часа работы);
- теперь вердикты сбрасываются в БД **каждые 1000 проверок** (и по границе партии):
  рестарт в середине партии теряет максимум последнюю сотню доменов;
- частота настраивается опцией `flushEvery` (по умолчанию 1000).

## Чекпоинт скана (переживает рестарт)

- состояние скана хранится в `Setting` (`dnsAliveScanState`): активен ли скан, origin,
  старт, кумулятивные счётчики (проверено/живых/мёртвых/ошибок/пропущено свежих);
- чекпоинт обновляется вслед за каждой записью вердиктов; завершение, ручная отмена и
  ошибка деактивируют его (автовозобновление не зацикливается).

## Автовозобновление при старте контейнера

- `instrumentation.ts` при старте процесса вызывает `maybeResumeInterruptedScan`:
  активный чекпоинт = «процесс умер посреди скана» → скан **продолжается автоматически**
  (origin `resume`);
- свежие вердикты из БД не перепроверяются (TTL `dnsAliveTtlDays`) — работа не
  дублируется, скан фактически продолжается с места остановки;
- счётчики продолжаются с места остановки (UI показывает кумулятивный прогресс);
- в журнале появляется строка «скан был прерван рестартом контейнера — возобновляю с
  места остановки»;
- если фильтр неделегированных доменов выключен — чекпоинт просто гасится (рестарт
  скана не нужен: пользователь отключил фильтр).

## Постоянный журнал

- каждая партия (старт/объём/к проверке/пропущено свежих/итоги) и ключевые события
  (запуск, возобновление, завершение, отмена, ошибка) пишутся в постоянный журнал
  (`LogEntry` — вкладка «Журнал» в UI), дублируясь в stdout контейнера (`docker logs`);
- история скана переживает рестарт и видна без подключения к контейнеру.
