# v1.39.0 — переработка работы с БД; RST Cloud — полный API; меню настроек

## Инцидент «БД полностью блокирована» (продакшен, том 1.3 GB)

UI навсегда «Загрузка данных…», докатка схемы не выполнялась 10 дней.

**Корень:** db-heal перед ALTER'ами гонял «предохранительный» `VACUUM INTO` копии БД — на 1.3 GB/медленном диске не укладывался в 90 с, шаг помечался пропущенным, но брошенный запрос продолжал выполняться, а `await vacClient.$disconnect()` в finally ждал его МИНУТАМИ — глобальный таймаут рестарта (300 с) убивал процесс ДО ALTER'ов; недостающая таблица не создавалась никогда, при каждом рестарте всё повторялось, рядом копились частичные `.preheal`-копии (8 файлов ≈ 2.9 GB с горячими `-journal`).

## Переработка db-heal

- `VACUUM INTO` удалён как класс: докатка = метаданные, бэкап не нужен (полная копия — вручную при остановленном приложении);
- докатка всегда и первой;
- `CREATE INDEX` — best-effort (таймаут не проваливает запуск, повтор при рестарте);
- disconnect — гонка с 2 с, зависшие запросы не блокируют завершение;
- уборка мусора: частичные `.preheal` (с горячим журналом) удаляются при старте, старше двух свежих — тоже (`.bak-*` не трогаются, 2 свежих остаются кандидатами восстановления);
- тест +1 (16 сценариев db-heal).

## Приложение

- `/api/dashboard` не падает целиком — каждый блок под try/catch/бюджетом (деградация + `degraded[]` в ответе, UI показывает, что именно не ответило; WireGuard под бюджетом 8 с);
- докатка каталогов — один раз на процесс (опрос каждые 20 с больше не гоняет сверки каталогов по большой БД);
- sink-промисы против unhandledRejection (Node 22 — crash);
- «Обзор» при ошибке опроса — карточка ошибки с подсказкой и «Повторить» вместо вечного спиннера;
- `/api/health` печатает `probeLatencyMs` (простой запрос > 5 с = «БД замедлена» — блокировка/перегрузка тома видны числом);
- `PRAGMA cache_size=32MB` + `temp_store=MEMORY` — горячие страницы большой БД в памяти.

## RST Cloud — полный API (api.rstcloud.net/v1, по официальному swagger 1.2.0 и rstapi-python)

- **фидбек IoC Lookup** — POST /v1/ioc «предложить индикатор» и PUT /v1/ioc «сообщить false positive»;
- **Noise Control batch** — пакетная проверка до 500 значений (POST /benign/batch/{type} → /benign/result/{type}, токен-поллинг);
- **RST Threat Library** — объекты угроз actors/malware/campaigns/ttps с filter/pagination (GET /threat-objects/{type});
- **Scan API** — Cobalt Strike beacon / SSL-сертификат / favicon / HTML (GET /scan/*);
- **RST CTI Assistant** — AI-чат (GET /models + POST /chat/completions);
- **RST Report Hub** — отчёты по дате + JSON/STIX/PDF (GET /reports);
- **Whois** — full/raw варианты.

Новые роуты: `/api/rst/{ioc,benign,assistant,reports,threat-objects,scan,whois}` (adminOnly, rate-limit, квота ключа); вкладка RST Cloud: ключ + проверка + фиды + IoC-диалог + батч-шум + библиотека + скан + AI-чат + отчёты.
