# v1.31.0 — «Аккаунт»: токены и доступ; DNS на «Обзоре» и в шапке

Развитие DNS-модуля v1.30.0 по обратной связи: места управления сгруппированы по
смыслу, статус DNS виден там же, где статус правил, — без открытия вкладок модуля.

## Раздел «Аккаунт»: токены и доступ переехали из «Сборки и экспорта»

- **Меню «Аккаунт»** (Enterprise) стало группой второго уровня, единообразно с
  остальными: **«Профиль и 2FA»** (прежний кабинет: данные учётной записи,
  смена пароля, Telegram/TOTP) и **«Токены и доступ»** (персональные токены
  скачивания со scope правила/домены/оба списка + готовые Uri отдачи);
- выдача токена — операция учётной записи, а не настройка сборки: карточка
  `TokensCard` вынесена из `build-tab.tsx` в отдельный `tokens-card.tsx`
  (вкладка `account-tokens-tab.tsx`), «Сборка и экспорт» стала компактнее;
- карточка сама вычисляет адрес отдачи из `window.location.origin` (адрес,
  с которого открыт хаб), готовые Uri по-прежнему БЕЗ токена — токен
  вставляется в поле «Optional authorization key» источника Clear NDR;
- контракты API не изменились: `GET/POST /api/tokens`, `DELETE /api/tokens/:id`,
  scope нормализуется при создании; у пользователя — только свои токены,
  у администратора — все с владельцами;
- подсказки места выдачи обновлены во всех текстах: ошибки отдачи правил
  (`serve.ts`) и списка доменов (`dns-serve.ts`), подсказка на вкладке сборки
  DNS (`dns.tokensHint`), help-tab, README/README.en, architecture(.en),
  docs/developer.md, docs/clearndr-integration.md(.en), openapi.json.
  Community не затронут: токены существуют только в Enterprise, меню «Аккаунт»
  в Community по-прежнему не показывается.

## DNS-фильтрация на «Обзоре» — аналогично правилам

- Вторая строка карточек показателей (администратор, когда модуль включён):
  **DNS источники** (включено/всего · ошибок), **Доменов в базе**, **Категорий
  списков**, **Доменов в сборке DNS** (файл · размер);
- карточка **«Последняя сборка списка доменов»** — как у правил: файл, размер,
  время, число доменов, SHA-256 и кнопка **«Скачать список доменов»**
  (`GET /api/dns/export` — по сессии администратора);
- данные приходят из уже существующего блока `dns` дашборда (`domainDashboard()`),
  новый код — только отображение; пользователь Enterprise блок не получает
  (`dns: null`), карточки у него не показываются.

## Плашки статуса DNS в шапке — аналогично правилам

- **«{n} доменов в базе»** — рядом с «{n} правил в базе»;
- **«DNS: {ok}/{enabled} ОК»** — рядом с «Источники: {ok}/{enabled} ОК»;
  жёлтая, когда есть DNS-источники в состоянии ошибки;
- обе — только администратору (Community — тоже админ), в общий размер шапки
  укладываются переносом строк (липкий блок адаптируется сам).

## Сквозная проверка

- Enterprise (сессия администратора, браузер): меню «Аккаунт» — группа с «Профиль и
  2FA» и «Токены и доступ»; карточка токенов отдаёт готовые Uri из адресной строки;
  токен со scope «домены» создаётся в «Аккаунт → Токены и доступ», плашки шапки
  «{n} доменов в базе» и «DNS: 1/45 ОК», строка DNS-карточек и карточка последней
  сборки с кнопкой скачивания — на «Обзоре»; RU/EN переключаются;
- Community (браузер): меню без «Аккаунта» (токенов нет), DNS-плашки шапки и
  DNS-карточки «Обзора» на месте (роль Community — администратор);
- API: токен scope «domains» проходит аутентификацию на `GET /api/dns/export`
  (404 «файл не найден — пересоберите» на пустом диске — ключ принят), а
  `GET /api/export` с ним отвечает 403 с подсказкой нового места выдачи
  («Аккаунт» → «Токены и доступ»); пользователь Enterprise видит только свои
  токены, администратор — все (тесты).
